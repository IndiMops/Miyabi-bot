# Конфігурація

[← До змісту](README.md)

Конфігурація складається з двох частин:

- `.env` — секрети та локальний режим запуску;
- [`config.json`](../config.json) — публічні налаштування бота й embeds.

Обидва файли читаються під час імпорту модулів. Після будь-якої зміни
перезапусти процес бота.

## Змінні середовища

| Змінна | Обов'язкова | Типове значення | Призначення |
|---|---:|---|---|
| `DISCORD_BOT_TOKEN` | так | немає | Секретний токен Discord Bot. Без нього `Config.require_token()` зупинить запуск із помилкою. |
| `DEBUG` | ні | `False` | Рівень консольних логів і керування завантаженням вимкнених cog-папок. |
| `STATUS_HEARTBEAT_URL`, `STATUS_HEARTBEAT_SECRET` та інші `STATUS_*` | ні | вимкнено | Heartbeat у status service. Див. [Моніторинг статусу](status-monitoring.md). |

Шаблон без секретів — [`.env.example`](../.env.example).

`DEBUG` стає істинним лише тоді, коли значення дорівнює `true` без урахування
регістру. Значення `1`, `yes` або `on` у поточній реалізації означають `False`.

При `DEBUG=False` папки з `bot.disabled_cogs_folder` пропускаються. При
`DEBUG=True` цей список ігнорується, тому dev-модулі теж завантажуються.

> На момент створення документації локальне середовище було налаштоване на
> debug-режим. Перед звичайним або публічним запуском явно встанови
> `DEBUG=False`, бо dev-команди не обмежені власником бота.

## Поля `config.json`

### `bot`

| Поле | Формат | Де використовується |
|---|---|---|
| `name` | рядок | Назва в `/info`. |
| `prefix` | рядок | Передається в `commands.Bot`. Зараз prefix-команд немає, тому поле фактично не використовується. |
| `version` | рядок | Резервна версія для статусу, якщо Git hash отримати неможливо; також показується в `/info`. |
| `last_update` | Unix timestamp у секундах | Відносний час оновлення в `/info`. |
| `color.default` | `#RRGGBB` | Основний колір embeds. |
| `color.error` | `#RRGGBB` | Колір помилок; зараз майже не використовується. |
| `color.info` | `#RRGGBB` | Інформаційний колір; зараз майже не використовується. |
| `color.warn` | `#RRGGBB` | Попереджувальні embeds, наприклад «команди не знайдено». |
| `assets.avatar` | URL | Thumbnail/footer icon у відповідях. |
| `assets.banner` | URL | Banner у `/info`. |
| `assets.fallback_avatar` | локальний шлях | Зарезервовано, але поточний код fallback не застосовує. |
| `assets.fallback_banner` | локальний шлях | Зарезервовано, але поточний код fallback не застосовує. |
| `urls.support_server` | URL | Посилання на сервер підтримки в `/info`. |
| `urls.github` | URL | Посилання на репозиторій у `/info`. |
| `disabled_cogs_folder` | список рядків | Назви папок усередині `cogs/`, які пропускаються при `DEBUG=False`. |
| `commands` | список `{name, id}` | Discord command IDs для клікабельних згадок виду `</help:ID>`. |

### `dev`

| Поле | Формат | Де використовується |
|---|---|---|
| `name` | рядок | Ім'я розробника в embeds. |
| `id` | цифровий рядок | Перетворюється на `int` і передається як `owner_id` бота. |
| `emoji` | Discord emoji markup | Іконка розробника в `/info`. |
| `website` | URL | Посилання у footer довідки. |

`owner_id` лише повідомляє `discord.py`, хто є власником. Він **не обмежує**
команди автоматично: для цього команда повинна мати окрему owner/permission
перевірку.

## Command IDs

Масив `bot.commands` не реєструє команди. Реєстрацію виконує
`bot.tree.sync()`, а IDs із JSON потрібні лише для красивих клікабельних
згадок усередині embeds.

Якщо запустити код з іншим Discord Application або перевидати команди:

1. Discord присвоїть нові IDs;
2. slash-команди працюватимуть;
3. старі згадки в `/help` та інших embeds можуть бути неправильними;
4. значення в `config.json` потрібно оновити вручну.

Поточний код не записує результат синхронізації назад у JSON.

## Важливі властивості

- `config.json` має залишатися валідним UTF-8 JSON без коментарів.
- Кольори повинні бути валідними HEX-рядками.
- `dev.id` повинен містити лише цифри.
- Назва в `disabled_cogs_folder` порівнюється з назвами папок у шляху модуля,
  а не з назвою окремого Python-файлу.
- Секрети не слід переносити з `.env` до `config.json`.
- Якщо JSON не читається, helper повертає порожній об'єкт, але наступне
  звернення на кшталт `Config.PUBLIC.bot` усе одно зламає імпорт.

## Чому варто запускати з кореня

[`utils/config.py`](../utils/config.py) шукає `.env` і `config.json` відносно
кореня проєкту. Водночас [`utils/logger.py`](../utils/logger.py) створює
`logs/` і відкриває файлові логи відносно поточної робочої директорії. Запуск
із кореня гарантує передбачуване місце для логів.
